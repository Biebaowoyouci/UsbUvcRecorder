# USB 摄像机录制 v1.7.3

原生 Android Camera2/UVC 预览、录制、设备切换、多设备分屏和 HDMI/USB-C 显示输出应用。最低 Android 8.0（API 26），compileSdk/targetSdk 36，面向 Android 12–16 做了权限、USB 热插拔、生命周期和全面屏适配。

## 主要功能

- 自动展开 Camera2 逻辑多摄像头中的物理镜头；例如一只逻辑后摄包含超广角、主摄和长焦时，会把三只物理镜头分别列出，并对厂商重复公开的 ID 去重。
- 同一逻辑相机下的多个物理镜头共用 CameraDevice/CaptureSession，通过 Physical Camera ID 路由各自画面，避免把同一组后摄当作多个逻辑 Camera 重复打开。
- 手机摄像头自动列出自身支持的 4K、1080P、720P 分辨率及可用帧率，点击“信号”或分屏中的对应画面即可切换，选择按 Camera ID 独立保存。
- 手机摄像头预览不再重复叠加 Camera2 `SurfaceTexture` 已包含的传感器旋转；按当前显示旋转校正方向，前摄镜像轴随 90°/270°同步切换。
- 单设备手机摄像头使用等比例居中裁边铺满全屏，X/Y 使用同一缩放系数，不拉伸也不缩成中间窄条；多设备分屏继续完整显示画面并保留空白区域手势。
- 多设备模式可混合选择手机摄像头、UVC 摄像头和采集卡，每路独立预览、独立录制文件；手机摄像头使用手机麦克风，UVC 继续使用对应 UAC/HDMI 嵌入音频。
- 全屏 UVC 预览；双击显示或隐藏控制层，显示设备、分辨率、格式、精确帧率、时长、容器、编码和码率。
- 枚举采集卡公布的 4K、1080、720 MJPEG/YUY2 P/i 格式及所有帧率；默认选择最大分辨率和该分辨率的最高帧率，模式及 USB 带宽档按 VID/PID 保存。
- “设备”按钮列出当前所有 UVC 摄像头和采集卡，切换后只打开所选设备，并持久保存单设备选择。
- “多设备”可多选 2–4 台设备，自动生成 2×N 分屏。每路使用定向 libuvc 会话、独立格式、独立预览路由和独立录制文件。
- 多设备错开 1.1 秒开流、编码器错开创建；单路 7 秒无帧只重启该路。USB 重新枚举后按设备特征自动找回，不拖黑其他画面。
- 多设备选择会保存；应用重启且所选设备均在线时自动恢复分屏。
- 多设备录制中某一路短暂掉线时，其他文件继续录制；该路恢复后自动建立新的续录文件。
- H.264/H.265 硬件编码；MP4、MOV、M4V、AVI 容器；可选码率、分段时长、手机/U 盘/移动硬盘保存位置。
- 单设备模式支持主/辅双路文件录制；主路开始时辅路同步开始，辅路可独立停止和重新开始。
- UAC/HDMI 嵌入音频编码为 AAC 48 kHz。单路显示一个电平表，多设备模式在每个输入画面右侧分别显示一只按画面宽度缩放的电平表；电平表跟随按钮透明度及双击显隐。
- 设置中的“多设备共享音源”默认关闭，此时各路只录自己一对一匹配的 UAC。开启后可从当前全部 Pocket/UVC/采集卡视频设备中手动指定一路作为共享音源；不会按音量自动切换，选择会持久保存。
- 录制 4 秒无视频样本会中止并删除空容器，避免生成约 3.2 KB 的损坏文件。
- 画面旋转 90° 同时作用于预览和录制，不拉伸；输出分辨率随 90°/270° 交换。
- “输出”可从当前单路/多路信号中选一路，或选择视频文件，通过手机 HDMI/USB-C 外接显示器播放并路由音频。
- 输出菜单固定列出每台设备的输出/环出状态。真实 UVC Video OUT 只在 USB 描述符存在 OUT 端点时标注；采集卡实体 HDMI LOOP OUT 由硬件自动环出，APP 不伪装成软件可写显示器。
- 文件页可查看全部、主路和辅路文件，点击交给系统播放器播放。

## 使用

1. 安装 `UsbUvcRecorder-v1.7.3-debug.apk`，授予相机、麦克风和 USB 权限。
2. 多设备高分辨率采集建议使用带独立供电的 USB 3 Hub；手机 OTG 口总线断电无法由软件恢复。
3. 双击画面打开控制层。用“设备”切换单路；用“多设备”勾选 2–4 路；在分屏中点击某个画面可选择该设备格式。
4. 所有分屏显示“已就绪”后点录制。每台设备生成 `MAIN_D01_设备名_时间.mp4` 形式的独立文件。
5. 设置中选择编码、容器、UAC、码率、分段、按钮透明度和保存位置；“多设备共享音源”可选关闭、Pocket 或任一当前采集卡；在设置页点“录制文件”查看结果。

## 硬件边界

- 手机同时打开多个 Camera2 摄像头的能力由厂商硬件和 HAL 决定；不支持并发的摄像头组合会在对应分屏明确显示打开失败，不会伪装成可并发。
- 输入端必须在 Android USB Host 中暴露标准 UVC VideoStreaming IN。普通 UVC 摄像头、常见 HDMI/SDI UVC 采集卡及 UVC 模式设备可用。
- 仅依赖 BMD Desktop Video、DeckLink/UltraStudio 私有驱动或 Thunderbolt 专有协议的设备不能模拟成 Android UVC；只有最终暴露标准 UVC 接口时才能打开。
- 采集卡实体 HDMI LOOP OUT 通常是硬件直通，Android 无法控制。USB VideoStreaming OUT 则需要设备公开可写端点和对应发送协议；APP 只按真实描述符报告，不虚构 BMD 桥接。
- 4K50/59.94、多路 4K、H.265 和多编码器并发取决于手机 USB 带宽、OTG 供电、散热及硬件编码器数量。
- 50i/59.94i 可按采集卡交付给 UVC 的帧录制，但通用 UVC 描述符不一定能可靠区分原始隔行与采集卡内部去隔行。

## 构建

- JDK 17
- Android SDK Platform 36
- Android Gradle Plugin 8.10.1 / Gradle 8.11.1
- Android NDK r28
- ABI：arm64-v8a、armeabi-v7a

```powershell
.\gradlew.bat assembleDebug
```

APK 输出：`app/build/outputs/apk/debug/app-debug.apk`。

## 本轮真机验证

- Xiaomi 25098PN5AC 的 Camera2 系统清单确认：逻辑后摄 `0` 公开物理镜头 `2/3/4`，逻辑前摄 `1`，应用按四个独立输入列出。
- v1.7.3 通过 USB ADB 真机覆盖安装；后置 Physical 4 与前置 Camera 1 均完成方向对比，物体保持竖直；全屏预览边界为 2656×1220，使用等比例中心裁边且无崩溃。
- Android 16 / API 36 真机安装、冷启动与设备选择持久化通过。
- Pocket 4：3840×2160 30p MJPEG 预览与 UAC 48 kHz 双声道电平通过。
- Cypress USB3.0 Capture Video：正确列出 1920×1080、1280×720 的 60/50/30/29.97/25p 模式。
- 多设备实际画面单击格式切换、空白区域双击控制层通过；UVC 自动恢复反复执行后未再出现 Android 16 `pthread_join` 原生崩溃。
- 共享关闭实录通过：USB3.0 路写入 373 个 AAC 音频样本和 1,516,800 字节 PCM；没有独立 UAC 的 Pocket 路保持 0 音频样本，确认没有误借用另一设备音频。
- 共享音源设置在真机正确列出 Pocket 4 与 USB3.0 Capture Video 两个视频设备，选择按设备保存；音频设备重新枚举时会按手动选择重新绑定，不做音量自动判断。
- 单路 4K MP4 约 15.8 秒实录包含 474 个视频样本、743 个音频样本和 3,033,600 字节 PCM，文件大小 49,626,584 字节。
- v1.6.4 双路同步基线实录通过：Pocket 4K30 文件包含 226 个视频/356 个音频样本，第二路 1080p60 文件包含 446 个视频/349 个音频样本；两份文件均写入 48 kHz 双声道 AAC，PCM 分别为 1,449,600 与 1,420,800 字节，错误均为 null。
